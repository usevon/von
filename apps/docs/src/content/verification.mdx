# Verifying Signatures

Verify that incoming webhooks are authentic and untampered using HMAC-SHA256 signatures.

<PageActions />

## How signing works

Every webhook Von delivers includes two headers:

| Header | Content |
| --- | --- |
| `X-Von-Signature` | `t={timestamp},v1={hmac_hex}` |
| `X-Von-Timestamp` | Unix timestamp in seconds |

The signature is computed as `HMAC-SHA256("{timestamp}.{raw_body}", secret)` where `secret` is the endpoint's signing key.

## Verifying with the SDK

The SDK provides a `verifyWebhook` function that handles parsing, timestamp validation, and timing-safe comparison:

```typescript
import { verifyWebhook, WebhookVerificationError } from "@usevon/sdk";

app.post("/webhooks", async (req) => {
  const payload = await req.text();
  const signature = req.headers.get("x-von-signature");

  try {
    const event = verifyWebhook(payload, signature, process.env.WEBHOOK_SECRET);
    console.log(event);
    return new Response("OK", { status: 200 });
  } catch (err) {
    if (err instanceof WebhookVerificationError) {
      return new Response("Invalid signature", { status: 401 });
    }
    throw err;
  }
});
```

<Properties>
  <Property name="payload" type="string" required>
    The raw request body as a string. Must be the exact bytes that were signed, not a parsed and re-serialized object.
  </Property>
  <Property name="signatureHeader" type="string" required>
    The value of the `X-Von-Signature` header.
  </Property>
  <Property name="secret" type="string" required>
    The endpoint's signing secret.
  </Property>
  <Property name="options.maxAge" type="number">
    Maximum allowed age of the timestamp in seconds. Defaults to 300 (5 minutes). Webhooks older than this are rejected.
  </Property>
</Properties>

## What the SDK checks

The verification function performs these checks in order:

1. Parses the signature header and extracts the timestamp and HMAC
2. Rejects timestamps more than 60 seconds in the future (clock skew protection)
3. Rejects timestamps older than `maxAge` (default 5 minutes)
4. Computes the expected HMAC and compares using timing-safe comparison
5. Parses the payload as JSON and returns the typed result

If any check fails, a `WebhookVerificationError` is thrown with a descriptive message.

## Verifying manually

If you are not using the SDK, here is the algorithm:

```typescript
import { createHmac, timingSafeEqual } from "crypto";

function verify(payload: string, header: string, secret: string) {
  const parts = Object.fromEntries(
    header.split(",").map((p) => {
      const [k, ...v] = p.split("=");
      return [k, v.join("=")];
    })
  );

  const timestamp = parseInt(parts.t, 10);
  const signature = parts.v1;

  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - timestamp) > 300) {
    throw new Error("Timestamp out of range");
  }

  const expected = createHmac("sha256", secret)
    .update(`${timestamp}.${payload}`)
    .digest("hex");

  const a = Buffer.from(signature);
  const b = Buffer.from(expected);
  if (a.length !== b.length || !timingSafeEqual(a, b)) {
    throw new Error("Invalid signature");
  }

  return JSON.parse(payload);
}
```

## Secret rotation

When you rotate an endpoint's secret, Von includes two signatures during the transition:

```
t=1700000000,v1=<current_hmac>,v2=<previous_hmac>
```

`v1` is signed with the current secret, `v2` with the previous. Your consumer can verify against either key. Once you have updated your consumer to use the new secret, call `DELETE /endpoints/:id/previous-secret` to finalize the rotation and stop including `v2`.

## Common mistakes

**Parsing the body before verifying.** If your framework parses the request body as JSON automatically, the re-serialized string may differ from the original. Always verify against the raw body string.

**Ignoring the timestamp.** Without timestamp validation, an attacker could replay a captured webhook indefinitely. The `maxAge` check prevents this.

**Using non-constant-time comparison.** A simple `===` comparison leaks timing information that can be used to forge signatures character by character. Always use `timingSafeEqual` or the SDK.
