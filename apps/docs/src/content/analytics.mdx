# Analytics

Use analytics endpoints to monitor delivery health, trend delivery volume, and measure retry behavior.

<PageActions />

## Access

Analytics routes accept API keys with `read:analytics`, `read:*`, or `*`.

## Endpoint pattern

Analytics routes follow `/analytics/{report}`:

| Endpoint | Use it for |
| --- | --- |
| `GET /analytics/overview` | Single-window totals and rates |
| `GET /analytics/timeseries` | Bucketed trend charts |
| `GET /analytics/retries` | Retry quality and attempt distribution |

## Shared query options

All analytics routes accept optional `from` and `to` ISO timestamp query params, and if both are set then `from` must be before or equal to `to`.

<Properties>
  <Property name="from" type="string">
    Optional ISO timestamp lower bound, inclusive.
  </Property>
  <Property name="to" type="string">
    Optional ISO timestamp upper bound, inclusive.
  </Property>
</Properties>

## Overview

Use `GET /analytics/overview` when you need a single snapshot for a time window.

It returns two groups:

- `totals` for event and delivery counts
- `rates` for success, failure, and retry percentages

Use this for cards and KPI summaries.

## Timeseries

Use `GET /analytics/timeseries` for line charts and trend views.

Buckets are grouped by delivery `createdAt`.

<Properties>
  <Property name="interval" type="string">
    Bucket size: `5m`, `15m`, `1h`, or `1d`. Defaults to `1h`.
  </Property>
</Properties>

### Interval values

| `interval` value | Meaning |
| --- | --- |
| `5m` | 5-minute buckets |
| `15m` | 15-minute buckets |
| `1h` | 1-hour buckets |
| `1d` | 1-day buckets |

### Bucket fields

| Field | Meaning |
| --- | --- |
| `ts` | Bucket start time in UTC |
| `deliveries` | Deliveries created in the bucket |
| `delivered` | Deliveries with status `delivered` |
| `failed` | Deliveries with status `failed` |
| `retries` | Deliveries where `attempts > 1` |
| `circuitOpen` | Deliveries with status `circuit_open` |

Buckets are sparse, so empty windows are omitted.

For `pending`, `paused`, and `skipped` counts, use `GET /analytics/overview`.

## Retries

Use `GET /analytics/retries` to understand retry quality across the selected range.

It returns:

- `totals`: delivery counts and retry outcomes
- `rates`: first-attempt success, retry rate, and recovery rate
- `attempts`: per-attempt-number breakdown

Use this for delivery-quality reporting and retry tuning.

| Group | Fields |
| --- | --- |
| `totals` | `deliveries`, `deliveriesWithRetry`, `recoveredAfterRetry`, `exhaustedRetries` |
| `rates` | `firstAttemptSuccessRate`, `retryRate`, `recoveredAfterRetryRate`, `averageAttemptsPerDelivery` |
| `attempts[]` | `attemptNumber`, `total`, `successes`, `failures` |

`attempts` only includes attempt indexes that occurred in the selected window.

## Query patterns

| Goal | Route pattern |
| --- | --- |
| Topline health for the last day | `GET /analytics/overview?from=...&to=...` |
| Trend chart for the last 48 hours | `GET /analytics/timeseries?from=...&to=...&interval=15m` |
| Weekly retry quality check | `GET /analytics/retries?from=...&to=...` |
