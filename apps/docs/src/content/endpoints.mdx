# Endpoints

Endpoints are the destination URLs where Von delivers your webhook events.

<PageActions />

## Creating an endpoint

Register a URL to start receiving webhooks. Von generates a unique signing secret for each endpoint automatically.

```typescript
const { data: endpoint } = await von.endpoints.post({
  url: "https://your-app.com/webhooks",
  description: "Production webhook receiver",
});
```

The response includes the endpoint's `secret`, which your consumer uses to verify signatures. This is the only time the secret is returned in full.

## Configuration options

<Properties>
  <Property name="url" type="string" required>
    The destination URL. Must be a public HTTPS URL. Von validates against SSRF by blocking private IP ranges, localhost, and cloud metadata endpoints.
  </Property>
  <Property name="description" type="string">
    A human-readable label for the endpoint.
  </Property>
  <Property name="status" type="string">
    One of `active`, `paused`, or `disabled`. Active endpoints receive deliveries normally. Paused endpoints queue deliveries with a `paused` status. Disabled endpoints skip deliveries entirely.
  </Property>
  <Property name="events" type="string[]">
    An array of event type patterns to subscribe to. When set, only matching events are delivered to this endpoint. Set to `null` to receive all events.
  </Property>
  <Property name="version" type="string">
    Pin this endpoint to a specific payload version. When set, Von applies the version's transforms before delivering.
  </Property>
  <Property name="maxAttempts" type="number">
    Maximum delivery attempts including the initial try. Range: 1 to 10. Defaults to 4.
  </Property>
  <Property name="timeoutMs" type="number">
    How long Von waits for a response before marking the attempt as failed. Range: 1000 to 60000. Defaults to 30000 (30 seconds).
  </Property>
</Properties>

## Event filtering

Endpoints can subscribe to specific event types using pattern matching.

| Pattern | Matches |
| --- | --- |
| `order.created` | Exact match only |
| `order.*` | Any event starting with `order.` |
| `*.created` | Any event ending with `.created` |
| `*` | All events |

When `events` is `null` or omitted, the endpoint receives everything. An empty array means the endpoint receives nothing.

```typescript
const { data: endpoint } = await von.endpoints.post({
  url: "https://your-app.com/webhooks",
  events: ["order.*", "invoice.paid"],
});
```

## Updating an endpoint

```typescript
await von.endpoints["ep_xxx"].patch({
  description: "Updated description",
  events: ["order.*"],
  maxAttempts: 6,
});
```

All fields are optional. Only the fields you include are updated.

## Test deliveries

Send a test webhook to verify your endpoint is reachable and responding correctly.

```typescript
const { data } = await von.endpoints["ep_xxx"].test.post({
  eventType: "von.test",
  payload: { message: "Hello from Von" },
});
```

This creates a real event and delivery that appears in the dashboard, so you can inspect the full request and response.

## Secret rotation

Rotate an endpoint's signing secret without downtime. During rotation, Von includes both the current and previous signatures in every delivery so your consumer can verify with either key.

```typescript
const { data } = await von.endpoints["ep_xxx"].rotate.post();
```

The response contains the new `secret` and the `previousSecret`. Both produce valid signatures until you finalize the rotation.

When your consumer has been updated to use the new secret, clear the previous one:

```typescript
await von.endpoints["ep_xxx"]["previous-secret"].delete();
```

During the rotation window, the `X-Von-Signature` header contains two signatures:

```
t=1700000000,v1=<current_secret_hmac>,v2=<previous_secret_hmac>
```

## Deleting an endpoint

```typescript
await von.endpoints["ep_xxx"].delete();
```

Deleting an endpoint also removes all associated delivery records.

## SSRF protection

Von validates endpoint URLs at creation time and again at delivery time:

- Private IP ranges are blocked (10.x, 172.16.x, 192.168.x, 127.x, etc.)
- Cloud metadata endpoints are blocked (169.254.169.254, metadata.google.internal, etc.)
- DNS resolution is checked at delivery time to catch DNS rebinding attacks
- Only `http` and `https` protocols are allowed
