# Retries & Recovery

Von handles delivery failures automatically with retries, circuit breakers, and replay.

<PageActions />

## Automatic retries

When a delivery fails (non-2xx response or timeout), Von retries it with exponential backoff starting at 1 second and doubling each attempt:

| Attempt | Delay |
| --- | --- |
| 1 | Immediate |
| 2 | ~1 second |
| 3 | ~2 seconds |
| 4 | ~4 seconds |

Each endpoint can configure its own `maxAttempts` (1 to 10, default 4) and `timeoutMs` (1 to 60 seconds, default 30 seconds).

```typescript
const { data: endpoint } = await von.endpoints.post({
  url: "https://your-app.com/webhooks",
  maxAttempts: 8,
  timeoutMs: 15000,
});
```

<Note>
  `maxAttempts` is the total number of attempts including the first try, not the number of retries after failure.
</Note>

A delivery is marked `failed` only after all attempts are exhausted.

## Circuit breakers

Von protects unstable endpoints with a circuit breaker, stopping delivery temporarily when an endpoint fails repeatedly to let it recover.

The circuit has three states:

Closed is the normal state where all deliveries flow through and Von tracks consecutive failures.

Open activates after 5 consecutive failures, with all deliveries immediately skipped as `circuit_open`.

Half-open activates after 5 minutes in the open state, allowing deliveries through to test recovery. A successful delivery closes the circuit and a failure reopens it for another 5 minutes.

| Parameter | Value |
| --- | --- |
| Failure threshold | 5 consecutive failures |
| Reset timeout | 5 minutes |

Only consecutive failures count toward the threshold. Any successful delivery resets the failure counter to zero.

<Tip title="Replaying circuit-skipped deliveries">
  Deliveries skipped while the circuit was open get a `circuit_open` status. Once the endpoint recovers, use bulk replay to re-deliver them.
</Tip>

## Replaying failed deliveries

### Single event

Re-deliver one event to all its endpoints, or target specific ones:

```typescript
await von.webhooks.events["evt_xxx"].replay.post({
  endpointIds: ["ep_abc"],
});
```

### Bulk replay

Re-deliver all failed deliveries since a given date:

```typescript
await von.webhooks.events.replay.post({
  since: "2025-01-15T00:00:00Z",
  status: "failed",
});
```

You can filter by `status` and `endpointId` to narrow the scope.

## Endpoint statuses

Only `active` endpoints receive deliveries. Changing status to `paused` or `disabled` affects future deliveries, not ones already in the queue.

| Status | Behavior |
| --- | --- |
| `active` | Deliveries are sent normally |
| `paused` | Deliveries in flight are marked `paused`, not attempted |
| `disabled` | Deliveries in flight are marked `skipped`, not attempted |

Pausing is useful during maintenance windows, since deliveries marked `paused` can be replayed once the endpoint is active again.

## Worker configuration

When self-hosting, you can configure the delivery worker:

| Variable | Default | Description |
| --- | --- | --- |
| `WORKER_CONCURRENCY` | 50 | Concurrent delivery jobs (max 500) |
| `EVENT_RETENTION_DAYS` | 90 | Days before events are cleaned up |
| `DELIVERY_RETENTION_DAYS` | 90 | Days before deliveries are cleaned up |
