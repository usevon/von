# Inbound Forwarding

Receive webhooks from third-party services through stable Von URLs, then forward them to your app with queueing and retries.

<PageActions />

## How it works

Point providers like Stripe or GitHub to a Von inbound endpoint instead of an app server directly. Von stores each incoming webhook, then forwards it to the configured app URL with the same retry and circuit-breaker behavior as outbound delivery.

The provider URL stays stable even if infrastructure changes, with retry handling, delivery tracking, and replay built in.

## Creating an inbound endpoint

```typescript
const { data: inbound } = await von.inbound.post({
  name: "Stripe Webhooks",
  provider: "stripe",
  forwardUrl: "https://your-app.com/webhooks/stripe",
});
```

The response includes the endpoint's `id` and `secret`. Third-party providers send webhooks to:

```text
https://api.usevon.com/in/{id}
```

<Properties>
  <Property name="forwardUrl" type="string" required>
    Where Von forwards received webhooks in your application.
  </Property>
  <Property name="maxAttempts" type="number">
    Retry attempts before marking a delivery failed. Defaults to `4` (min `1`, max `10`).
  </Property>
  <Property name="timeoutMs" type="number">
    Per-attempt request timeout in milliseconds. Defaults to `30000` (min `1000`, max `60000`).
  </Property>
  <Property name="name" type="string">
    A display label.
  </Property>
  <Property name="provider" type="string">
    The third-party service (e.g. `stripe`, `github`, `shopify`). Used for labeling only.
  </Property>
  <Property name="status" type="string">
    `active`, `paused`, or `disabled`. Defaults to `active`. Von automatically disables endpoints after 5 consecutive days of sustained forwarding failures.
  </Property>
</Properties>

## What Von forwards

When a webhook arrives at the inbound URL, Von:

1. Parses and stores the JSON payload and headers as an inbound delivery
2. Signs the forwarded request with an HMAC signature using the inbound endpoint's secret
3. Strips Von signature headers and sensitive headers (`authorization`, `host`) from the original request
4. Forwards the payload to your `forwardUrl` with Von delivery headers

The forwarded request includes an `X-Von-Inbound-Delivery-Id` header so you can correlate it with the original.

<Tip title="Verifying forwarded requests">
  Von signs forwarded requests with the inbound endpoint secret, so they can be verified with the same `verifyWebhook` helper used for outbound webhooks.
</Tip>

## Rate limiting

The public inbound endpoint (`/in/:id`) is limited to 100 requests per minute per IP and returns `429` with `Retry-After` when exceeded; see [Rate Limits & 429](/rate-limits) for retry guidance.

## Retries and circuit breakers

Inbound forwarding uses the same reliability features as outbound delivery:

- Automatic retries with exponential backoff (default 4 attempts)
- Circuit breaker that opens after 5 consecutive failures
- Configurable `maxAttempts` and `timeoutMs` per endpoint

Inbound forwarding endpoints share the same auto-disable rules as outbound endpoints and will be disabled after 5 days of sustained forwarding failures.

## Managing inbound endpoints

### Listing

```typescript
const { data } = await von.inbound.get({
  query: { limit: 20 },
});
```

### Getting one endpoint

```typescript
const { data } = await von.inbound["in_xxx"].get();
```

### Updating

```typescript
await von.inbound["in_xxx"].patch({
  forwardUrl: "https://new-app.com/webhooks/stripe",
  status: "paused",
});
```

### Deleting

```typescript
await von.inbound["in_xxx"].delete();
```

## Data retention

Von retains inbound deliveries for 90 days by default, and self-hosted deployments can change this with `INBOUND_DELIVERY_RETENTION_DAYS`.
