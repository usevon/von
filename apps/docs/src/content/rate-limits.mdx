# Rate Limits & 429

Von uses multiple limit layers to protect reliability.

## Limit layers

| Layer | What it limits | Current limit |
| --- | --- | --- |
| Auth request limit | API routes behind authentication | 200 requests/minute per IP |
| Public inbound limit | Provider traffic to `POST /in/:id` | 100 requests/minute per IP |
| Org throughput limit | Webhook delivery processing per organization | Token bucket by plan profile |

Authenticated-route limit coverage:

| Route group |
| --- |
| `/endpoints/*` |
| `/webhooks/*` |
| `/versions/*` |
| `/inbound/*` |

## Throughput details

Cloud pricing starts Metered throughput at 25/sec and allows higher throughput via add-ons.

Current delivery throughput profiles are:

| Profile | Refill rate | Burst |
| --- | --- | --- |
| `hobby` | 25 deliveries/second | 35 |
| temporary non-`hobby` fallback | 100 deliveries/second | 140 |

Throughput is enforced at the delivery worker level, not at API ingestion. When you send a webhook or receive an inbound event, the API always accepts the request and creates the event and deliveries. The worker then processes deliveries at the configured rate for your organization's plan. If delivery throughput is exceeded, jobs are delayed briefly and retried rather than rejected.

This means your API calls will never receive a `429` for throughput. Events are always persisted and deliveries are always queued.

## 429 response headers

When the IP-based request limit rejects a request, expect `429 Too Many Requests`.

Responses include:

| Header | Meaning |
| --- | --- |
| `X-RateLimit-Limit` | Window max |
| `X-RateLimit-Remaining` | Remaining requests in current window |
| `X-RateLimit-Reset` | Unix timestamp when the window resets |
| `Retry-After` | Seconds to wait before retrying |

## Handling 429 correctly

1. Read `Retry-After` if present.
2. Retry with jittered backoff.
3. Keep idempotency enabled on mutating requests.

```typescript
async function requestWith429Retry(input: RequestInfo, init?: RequestInit) {
  for (let attempt = 0; attempt < 5; attempt += 1) {
    const res = await fetch(input, init);
    if (res.status !== 429) {
      return res;
    }

    const retryAfter = Number(res.headers.get("retry-after") ?? "0");
    const baseDelayMs = retryAfter > 0 ? retryAfter * 1000 : 500 * 2 ** attempt;
    const jitterMs = Math.floor(Math.random() * 200);
    await new Promise((resolve) => setTimeout(resolve, baseDelayMs + jitterMs));
  }

  throw new Error("Exceeded retry budget after repeated 429 responses");
}
```
