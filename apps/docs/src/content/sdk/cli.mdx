Forward webhooks to your local machine with secure tunnels for development and debugging.

## Authentication

Log in using the device authorization flow. The CLI opens your browser for you to approve access.

```bash
von login
```

For self-hosted instances:

```bash
von login --api-url https://your-von-api.com
```

For local development against a local Von server:

```bash
von login --local
```

## Starting a tunnel

Forward webhooks to a local port:

```bash
von dev -p 3000
```

This registers a tunnel and prints the public URL:

```
https://api.usevon.com/t/{tunnelId}-{secret}
```

Point your webhook provider or Von endpoint at this URL. All requests are forwarded through a WebSocket connection to your local machine.

### Multiple ports

Forward to up to 3 local ports simultaneously:

```bash
von dev -p 3000 -p 3001 -p 4000
```

Each port gets its own tunnel URL.

### Verbose mode

See full request and response details:

```bash
von dev -p 3000 --verbose
```

This prints headers, body previews, response status codes, and timing for each request.

## How tunnels work

1. The CLI registers a tunnel with the Von API and receives a unique ID and secret
2. A WebSocket connection is established from your machine to the Von server
3. When a request arrives at the tunnel URL, Von forwards it through the WebSocket
4. The CLI makes a local HTTP request to `localhost:{port}` and sends the response back

If your local server is down or times out (30 seconds), the tunnel returns a 502 response.

## Reconnection

If the WebSocket connection drops, the CLI reconnects automatically with exponential backoff (2s, 4s, 8s, 16s, 30s). After 5 failed reconnection attempts, the tunnel is removed.

## Rotating tunnel secrets

Invalidate the current tunnel URL and generate a new one:

```bash
von rotate -p 3000
```

If a tunnel is actively running, the new URL is displayed in the `von dev` output automatically.

## Organization management

### Check status

```bash
von status
```

Shows the current user, organization, and API URL.

### Switch organization

```bash
von switch
```

Displays an interactive picker to change the active organization.

### Log out

```bash
von logout
```

Clears the stored token and organization from `~/.von/config.json`.

## Command reference

| Command | Description |
| --- | --- |
| `von login` | Authenticate with Von |
| `von logout` | Clear stored credentials |
| `von status` | Show current user and organization |
| `von switch` | Switch active organization |
| `von dev -p <port>` | Start tunnel to local port |
| `von rotate -p <port>` | Rotate tunnel secret |

### Login flags

| Flag | Description |
| --- | --- |
| `-l, --local` | Use localhost:8080 as the API URL |
| `--api-url <url>` | Custom API URL |
| `-f, --force` | Re-login even if already authenticated |

### Dev flags

| Flag | Description |
| --- | --- |
| `-p, --port <port>` | Local port to forward to (required, repeatable, max 3) |
| `-v, --verbose` | Show detailed request/response info |

## Configuration

The CLI stores its config at `~/.von/config.json` with `0600` permissions:

```json
{
  "apiUrl": "https://api.usevon.com",
  "token": "...",
  "organizationId": "..."
}
```

Logging out in another terminal while `von dev` is running will automatically shut down active tunnels.
