# Payload Versioning

Evolve your webhook payloads without breaking existing integrations.

<PageActions />

## How it works

Webhook versions define transforms that modify payloads before delivery. Each endpoint can be pinned to a specific version, so consumers on older schemas keep receiving the format they expect while you ship new fields and structures.

## Creating a version

Versions are identified by a string (typically a date like `2025-01-15`). Each version contains transform mappings keyed by event type.

```typescript
await von.versions.post({
  version: "2025-01-15",
  transforms: {
    "order.created": {
      rename: { "line_items": "items" },
      remove: ["internal_notes"],
      defaults: { "api_version": "2025-01-15" },
    },
    "order.updated": {
      remove: ["internal_notes"],
    },
  },
});
```

## Transform operations

Transforms are applied in order before the payload is signed and delivered:

1. Remove: deletes specified top-level fields from the payload.
2. Rename: moves values from one key to another, only if the source field exists.
3. Defaults: adds fields with default values, only if the field is not already present.

<Properties>
  <Property name="remove" type="string[]">
    Top-level fields to delete.
  </Property>
  <Property name="rename" type="Record<string, string>">
    Old-to-new field name map. Values are moved, not copied.
  </Property>
  <Property name="defaults" type="Record<string, unknown>">
    Fields to inject when not already present in the payload.
  </Property>
</Properties>

## Example

Given this payload:

```json
{
  "orderId": "order_123",
  "line_items": [{ "sku": "A1", "qty": 2 }],
  "internal_notes": "rush order",
  "total": 99.99
}
```

With these transforms:

```json
{
  "rename": { "line_items": "items" },
  "remove": ["internal_notes"],
  "defaults": { "currency": "usd" }
}
```

The delivered payload becomes:

```json
{
  "orderId": "order_123",
  "items": [{ "sku": "A1", "qty": 2 }],
  "total": 99.99,
  "currency": "usd"
}
```

## Pinning an endpoint to a version

Set the `version` field when creating or updating an endpoint:

```typescript
await von.endpoints.post({
  url: "https://partner-app.com/webhooks",
  version: "2025-01-15",
});
```

When Von delivers to this endpoint, it looks up the version's transforms for the event type and applies them before signing. Endpoints without a version receive the original payload.

## Updating a version

```typescript
await von.versions["2025-01-15"].patch({
  transforms: {
    "order.created": {
      rename: { "line_items": "items" },
      remove: ["internal_notes", "debug_info"],
      defaults: { "api_version": "2025-01-15" },
    },
  },
});
```

## Listing versions

```typescript
const { data } = await von.versions.get({
  query: { limit: 20 },
});
```

<Tip title="Cache delay after updates">
  Version transforms are cached in Redis with a 60-second TTL. After updating a version, allow up to 60 seconds for changes to apply to new deliveries.
</Tip>
